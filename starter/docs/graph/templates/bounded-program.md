# Bounded development run

This is an operating contract template, not permission to execute.
Execution is disabled until the project owner approves a completed packet
and the runtime confirms all required controls can be enforced.

## Before work
1. Read the approved task and policy references; verify their revisions.
2. Inspect the actual baseline and preserve dirty files and worktrees.
3. Verify required prerequisites, capability scope, and budget reservations.
4. Read the generated context packet and its omissions and conflicts.
5. Stop if mandatory evidence or the expected integration is unavailable.

## During work
- Work on one approved packet in the assigned isolated scope.
- Reuse existing architecture and interfaces unless the packet authorizes change.
- Do not alter protected evaluation or permission policy.
- Record candidate artifacts with exact inputs and versions.
- Run registered verification commands; retain actual output and exit status.
- Propose graph updates with sources and uncertainty. Do not self-certify them.
- Count all descendants, tool calls, retries, and repairs against aggregate limits.
- Do not send private data to an undeclared destination.

## Review and repair
- Supply the exact candidate, diff, criteria, and observed evidence.
- A fresh reviewer returns criterion-level defects and unresolved gates.
- Make only bounded repairs within the remaining budget.
- A changed candidate requires reassessment of affected evidence.
- Escalate repeated conceptual failure instead of widening scope silently.

## Stop conditions
Stop on exhausted limits, missing authority, unsafe or ambiguous external
state, unresolved baseline identity, or repeated non-progress.
Preserve the best candidate, evidence, failed approaches, and next safe action.
A stopped, blocked, or skipped check is never a pass.

## Publication
No push, merge, deployment, purchase, or external-source mutation is
inherited from this document. Each requires its own scoped authorization.

## Return
Return a structured run receipt plus a concise human summary:
what changed; exact candidate; what passed; what failed or was unrun;
remaining questions; actual usage or unknown counters; next safe action.
